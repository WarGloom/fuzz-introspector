
## 2025-03-05 - Optimize Multimap Accumulation
**Learning:** Using `dict.setdefault(key, []).append(...)` for accumulating values into lists allocates an empty list on every single iteration, creating significant garbage collection pressure and CPU overhead in tight loops parsing debug info and profiling data. `collections.defaultdict(list)` avoids this allocation overhead and operates 30-50% faster.
**Action:** Always prefer `collections.defaultdict(list)` (or `set`) when constructing dictionary multimaps.

## 2025-03-05 - Optimal Targets Hitcount Update Optimization
**Learning:** In `optimal_targets.py`, the `add_func_to_reached_and_clone` function had an $O(N \times M)$ loop to recalculate `new_unreached_complexity` and `total_cyclomatic_complexity` for all functions upon each fuzzer selection. Because `functions_reached` represents the full transitive closure (rather than direct edges), tracking via `incoming_references` is insufficient to find all indirect callers that depend on a function. Instead, decrementing `new_unreached_complexity` via a direct scan of `all_functions` against only the newly hit functions (an $O(N \times K)$ loop, where K is tiny) is correct and extremely fast. Static properties like `total_cyclomatic_complexity` do not need recomputation.
**Action:** Always prefer updating aggregations incrementally rather than recomputing them entirely from scratch, but be careful to respect whether internal caching arrays like `functions_reached` store transitive or direct edges to maintain accurate semantics. Avoid recomputing static properties repeatedly in simulation loops.
